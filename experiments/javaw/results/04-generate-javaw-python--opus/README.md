# javaw

`javaw` generates a small, relocatable POSIX `sh` launcher script for a Java program.
The generated wrapper is the product; `javaw` is never in the launch path.
It needs Python 3.9+ and nothing else.

## Usage

```sh
./javaw Tool.java                          # writes ./run-tool -> exec java "$dir/Tool.java" "$@"
./javaw --jar my-tool.jar                  # writes ./run-my-tool -> exec java -jar "$dir/my-tool.jar" "$@"
./javaw --min-java 17 --jvm-opts "-Xmx1g" --classpath 'lib/*' \
        --java-home /opt/jdk-21 -o bin/tool src/Tool.java
./javaw -o bin/ FooBar.java HTTPServer.java  # bin/run-foo-bar, bin/run-http-server
./javaw --force Tool.java                  # overwrite an existing wrapper
./javaw --help
```

Try it with the bundled example:

```sh
cd examples
../javaw --min-java 17 Hello.java
./run-hello world                 # Hello world (app.version=1)
cd / && "$OLDPWD/run-hello" again  # works from any directory, and through symlinks
```

## What a wrapper looks like

```sh
#!/bin/sh
# Generated by: javaw --min-java 17 Hello.java
self=$0
while [ -L "$self" ]; do
  link=$(readlink -- "$self")
  case $link in
    /*) self=$link ;;
    *) self=$(dirname -- "$self")/$link ;;
  esac
done
dir=$(dirname -- "$self")
case $dir in /*) ;; *) dir=./$dir ;; esac
dir=$(CDPATH= cd -P -- "$dir" && pwd -P) || exit 1
found=$(java -version 2>&1 | sed -n 's/^[^ ]* version "\([^"]*\)".*/\1/p' | head -n 1)
major=${found#1.}
major=${major%%[!0-9]*}
if [ -z "$major" ] || [ "$major" -lt 17 ]; then
  echo "error: Java 17 or newer is required (found: ${found:-no usable java})" >&2
  exit 1
fi
exec java "$dir/Hello.java" "$@"
```

The version check block appears only with `--min-java`. Plain `readlink` (without `-f`)
ships with stock macOS and Linux. Relative directories get a `./` prefix so `cd` never
consults `CDPATH` or reads a leading `-` as an option. The program path is stored
relative to the wrapper, so the wrapper and its siblings can be moved together.

## Tests

```sh
python3 -m unittest -v test_javaw.py
```

The tests cover kebab-case naming, CLI errors, output naming, overwrite protection,
and option rendering. They check version parsing (`1.8.0_x`, `28-ea`, JAVA_TOOL_OPTIONS
notices, missing java) against fake JVMs. If `java` is on the PATH, they also run
`examples/Hello.java` end to end: from another directory, after moving and renaming, through a
relative symlink and a chain of two, with `JAVA_TOOL_OPTIONS=-Dapp.version=2`, with `CDPATH`
exported and a relative invocation matching a `CDPATH` entry, under `dash`/`sh`/`bash`, and as
a jar.
