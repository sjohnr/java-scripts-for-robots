# javaw

`javaw` generates a small, relocatable POSIX `sh` launcher script for a Java
program. The generated wrapper is the product: `javaw` never builds, bundles,
or launches anything. Requires Node.js 18+ (no dependencies).

## Usage

```sh
./javaw Tool.java                       # writes ./run-tool
./javaw --jar lib/tool.jar -o bin/      # writes bin/run-tool -> java -jar "$dir/../lib/tool.jar"
./javaw --min-java 17 --jvm-opts "-Xmx512m -Dmode=prod" \
        --classpath 'lib/*' --java-home /opt/jdk-21 -o serve HTTPServer.java
./javaw A.java B.java -o bin/           # one wrapper per input
./javaw --force Tool.java               # overwrite an existing wrapper
./javaw --help
```

Install it on your PATH with `npm link` (or copy/symlink `javaw`).

The program path in the wrapper is relative to the wrapper's real location, so
move the wrapper together with the program (renaming it is fine). Symlinks to
the wrapper (relative, absolute, or chained) work too. `--jvm-opts` is split on
whitespace. `--classpath` and `--java-home` are recorded as given.

Example generated by `javaw --min-java 17 Hello.java`:

```sh
#!/bin/sh
# Generated by javaw. Regenerate with:
#   javaw --min-java 17 Hello.java
self=$0
while [ -L "$self" ]; do
  link=$(readlink -- "$self") || exit 1
  case $link in
    /*) self=$link ;;
    *) self=$(dirname -- "$self")/$link ;;
  esac
done
dir=$(CDPATH= cd -P -- "$(dirname -- "$self")" && pwd -P) || exit 1
v=$(java -version 2>&1 | sed -n 's/^[^ ]* version "\([^"]*\)".*/\1/p' | head -n 1)
n=${v#1.}
n=${n%%[!0-9]*}
if [ -z "$n" ] || [ "$n" -lt 17 ]; then
  echo "${0##*/}: Java 17 or newer is required (found: ${v:-no usable java})" >&2
  exit 1
fi
exec java "$dir/Hello.java" "$@"
```

## Tests and verification

```sh
npm test        # or: node --test
```

The tests use `node:test` and `node:assert` and need no setup. They cover:
kebab-case naming, quoting, CLI errors, wrapper contents (including that unused
options are absent), output naming and overwriting, and `--min-java` against a
fake JDK (`1.8.0_x` → 8, `28-ea` → 28, `JAVA_TOOL_OPTIONS` notices, garbage
output, missing `java`). If a JDK is installed, they also run
`examples/Hello.java` through generated wrappers:

- from a different working directory
- through a relative symlink and a chain of two symlinks
- with `JAVA_TOOL_OPTIONS=-Dapp.version=2`
- with `CDPATH` exported and the wrapper invoked as `app/run-hello` while `$CDPATH/app` exists
- through a path starting with `-`, and after moving and renaming the wrapper
- as a `java -jar` wrapper around a jar built from the example
